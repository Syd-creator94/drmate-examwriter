# Clinic: локальный UX-прототип

Проверенный рабочий вариант от 10 сентября 2026 года. Документ предназначен для
продолжения разработки и оценки интерфейса врачом; обновляется вместе с
поведением прототипа. Источник реализации — `src/dr_mate_clinic_prototype`,
проверок — `tests/clinic_prototype`.

## Запуск

Из корня репозитория:

```bash
PYTHONPATH=src .venv/bin/python -m dr_mate_clinic_prototype
```

Открыть `http://127.0.0.1:8766/`. Другой порт: `--port 8767`.
После установки текущего пакета доступна команда `drmate-clinic-demo`.
Сервер слушает только loopback и отдаёт разрешённые статические ресурсы.

## Что проверить вручную

1. Ввести значение в рефракцию. Перейти к спецификациям коррекции и обратно:
   введённое значение должно остаться. Кнопки разделов и стрелки заголовков
   меняют фокус; ввод в поле не перестраивает экран.
2. Выбрать один из пяти последних осмотров или запись в общем списке.
   Основная область ещё не меняется. Нажать «Открыть рядом», выбрать пропорции
   и расположение, раскрыть вторую область, затем вернуться к сравнению.
3. Искать `перерыв` и `washout`: оба запроса находят учебный осмотр #14680.
   Поиск `ОКТ`/`OCT` находит схему и текстовый документ. Каждый результат можно
   открыть основным или рядом. Открыть изображение и документ одновременно,
   поменять области местами, увеличить изображение.
4. В спецификациях КЛ нажать «Параметр», выбрать глаз и название, явно указать
   известную единицу. Новое поле относится только к этой коррекции и глазу.
   Стрелки у Flex-поля меняют его положение. Исторические снимки не меняются.
5. Добавить DVID, заполнить значение, завершить демо-осмотр с решением врача
   и создать следующий. Поле остаётся видимым, но новое значение пустое;
   прежнее находится рядом с датой.
6. Ввести авторефракцию вручную и загрузить демо-пакет: ручное значение не
   перезаписывается. Просмотр исходного пакета сохраняется после правок.
7. Переключить светлую, тёмную и автоматическую темы. Обновить страницу:
   выбранная тема и введённые данные должны сохраниться в пределах указанного
   ниже демонстрационного хранения.

## Реализация и границы

- `model.mjs`: синтетический сценарий, измерения, снимки коррекции на дату
  визита, исходные демо-пакеты, завершение записи и локальные follow-up.
- `workspace.mjs`: выбор отдельно от открытия, основная/параллельная области,
  обратимый переход в материал, поиск по карте и параметры конкретного глаза.
- `app.mjs` и `styles.css`: формы, темы, плотная компоновка, просмотр материалов
  и Mechanicus-декор по пользовательским концептам cogOS без ромба.
- `sessionStorage` сохраняет учебную карту после обновления этой вкладки.
  Это не клиническое хранилище и не синхронизация между рабочими местами.
  `localStorage` хранит только предпочтение темы.
- Добавление учебных материалов в старый сценарий выполняется аддитивно:
  существующие изменения v1 сохраняются. Сброс демо требует явного действия.
- Поиск ограничен записями этой синтетической карты и текстом/метаданными
  встроенных материалов. Фразы связаны небольшим явным словарём синонимов;
  клиническое состояние не выводится из числовых результатов.
- Изображения — явно обозначенные SVG-схемы. Документ — встроенный учебный
  текст. Загрузка реальных фото/PDF, PDF viewer, OCR и индексация реального
  архива не реализованы.
- Реальные приборы, пациентский реестр, API Clinic, авторизация, серверное
  сохранение, подпись, резервное копирование, общий Follow-up и clinical
  decision support не подключены. Завершение — состояние UX-прототипа.
- Base/Flex повторяет взаимодействие из Lens Order Management, но не
  утверждает manufacturer-профили, ranges или интеграционный контракт.
  Источники образца: LOM `app/components/SpecEditor.tsx`,
  `lib/spec-templates.ts`, ADR-0008. Эти файлы не изменялись.
- Новая компоновка — проверяемая реализация обсуждённого UX. Она не меняет
  ADR по clinical runtime, privacy или клиническим правилам.

## Проверки

```bash
node --test tests/clinic_prototype/*.test.mjs
.venv/bin/python -m pytest
.venv/bin/ruff check src tests
.venv/bin/mypy src
.venv/bin/python -m build --no-isolation
```

На 10.09.2026: 12 Node-тестов и 41 Python-тест прошли; Ruff, mypy и сборка
прошли. Wheel содержит все семь статических ресурсов Clinic и CLI entrypoint.
Интерактивно проверены выбор без перехода, сравнение и возврат, поиск синонимов,
просмотр схемы/документа, масштаб изображения, Flex OD отдельно от OS,
сохранение ввода, темы и два WebMCP-действия (включая ошибочный ID).
Встроенный Playwright Chromium не установлен; UI проверялся через браузер
Codex. Восстановление состояния ОС при смене темы вручную не тестировалось;
авто-режим сопоставлен с текущим `prefers-color-scheme`, listener установлен.

Следующий шаг для продуктовой оценки — пройти сценарий с врачом и сопоставить
компоновку с его следующим рисунком. Подключение реальных данных требует
отдельной работы по согласованному плану Clinic.

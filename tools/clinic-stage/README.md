# Dr. Mate · Clinic stage

Новое интерактивное представление Clinic и отдельный фронтенд CRM. Все поверхности и компоненты написаны заново, с опорой на актуальный Flux от 07.10.2026. Старый дизайн Clinic не используется. Исходные проекты Dr. Mate и Flux не изменены.

## Посмотреть

[Опубликованный приватный просмотр Clinic и CRM](https://dr-mate-clinic-stage.afarbitnik.chatgpt.site). Для доступа используется вход владельца через ChatGPT.

Откройте `dist/clinic-stage.html` прямо в браузере: это самостоятельный файл со встроенными стилями, кодом и графикой. Сеть и установка зависимостей для просмотра не нужны.

Для разработки из этой папки:

```sh
python3 tools/serve.py --port 8788
```

Затем откройте `http://127.0.0.1:8788/`. Сервер слушает только локальный адрес. Изменения исходников видны после обновления страницы; переносной файл пересобирается командой `npm run build`.

## Маршрут просмотра

Для первого знакомства есть [короткий маршрут на 5–7 минут](docs/review-route.md) с конкретными вопросами для оценки.

1. Clinic → «Рабочий день» → карта Марии Соколовой. Обзор показывает шесть тематических карточек и контекст визита.
2. Разверните рефракцию, измените поле, перейдите к линзам и вернитесь. Ввод остаётся на месте. «Сравнить» открывает датированный исторический осмотр рядом, «Закрепить» добавляет ссылку на источник в контекст.
3. В «Истории» откройте завершённый визит: он доступен только для чтения. Для нового визита после завершения наблюдения начинаются пустыми. Точки и счётчик разделов показывают наличие ввода, а не клиническую полноту или качество осмотра.
4. Clinic → «Пациенты» и «Материалы». Учебные схемы можно открыть в просмотрщике; в контексте есть шесть слотов для локальных PNG/JPEG/WebP/GIF/PDF/TXT до 20 МБ.
5. CRM → «Сегодня» → «Обращения». Создайте вымышленное обращение, откройте карточку и задайте ответственного, следующий шаг и этап.
6. CRM → «Расписание» → «Неделя». Семь дней Пн–Вс, число записей и занятое время по дням; стрелки переключают недели. Нажмите заголовок дня для подробного дневного вида или свободный получасовой слот для записи на точную дату. На узких экранах календарь прокручивается внутри своей области. Пересечения времени блокируются. В «Выдаче и контроле» есть сценарии с указанным планом и без плана врача.
7. Переключите тему. На небольших экранах очередь и контекст открываются отдельными панелями; разделы приёма прокручиваются горизонтально.

## Границы версии

Данные полностью вымышленные. Дата учебного рабочего дня фиксирована: 08.10.2026. Прототип предназначен для оценки интерфейса; реальных пациентов вводить сюда не следует.

Кнопки «Сохранить» явно сохраняют данные только в хранилище этого браузера. Clinic сохраняется по пациенту, CRM — отдельно. Тема сохраняется как предпочтение. Изменения в другой вкладке обнаруживаются перед перезаписью. Локальные файлы остаются в памяти вкладки и после перезагрузки выбираются снова. При недоступном хранилище интерфейс оставляет работу в памяти и сообщает об ошибке.

Нет серверной медицинской карты, авторизации ролей, звонков, сообщений, реального импорта приборов или API-интеграций. «Демо-пакет» заполняет только пустые поля авторефракции учебными значениями; ручной ввод не заменяет. Манифестная рефракция, авторефракция и отдельно измеренная Vis OU остаются различными данными. CRM показывает операционные сведения и не получает клинические измерения. Переход из CRM в Clinic здесь демонстрирует границу модулей, а не систему разграничения доступа.

## Проверка

```sh
npm install
npm run check
npm test
npm run build
```

Для приложения зависимости не нужны; `jsdom` используется только в интеграционных тестах. Проверены изоляция пациентов/OD/OS, исторические записи, пустой новый приём, ввод между представлениями, ожидания конкретного осмотра, датированные закрепления, сохранение и восстановление, конфликт вкладок, отказ хранилища, разделение Clinic/CRM, экранирование текста, запрет пересечений записи и выдачи без плана.

Браузерная проверка охватила светлую и тёмную темы, десктоп, планшет и мобильную ширину. Снимки находятся в `artifacts/`. Подробная оценка концепции и дальнейшие вопросы — в `docs/design-review.md`.

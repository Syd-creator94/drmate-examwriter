# Dr. Mate: обзор проекта

## Назначение

Dr. Mate — проект поддержки работы врача-офтальмолога: сбор и нормализация клинических данных, подготовка заключений и развитие объяснимых вспомогательных инструментов для клинических решений.

## Принятые направления

- `DECIDED`: стабильный корень проекта находится в `Documents/Codex/projects/dr-mate`.
- `DECIDED`: существующий ExamWriter-прототип является текущим техническим ядром Dr. Mate, а не отдельным конечным продуктом.
- `DECIDED`: интеграции с источниками данных должны быть отделены от универсальной медицинской модели и от представления результатов.
- `DECIDED`: база моделей контактных линз должна одновременно поддерживать быстрый врачебный справочник и будущий модуль объяснимого поиска потенциальных кандидатов.
- `DECIDED`: результат поиска контактных линз является списком кандидатов для проверки врачом, а не автоматическим рецептом или подтверждением клинической пригодности.
- `DECIDED`: первым пилотным источником для проектирования каталога контактных линз будет официальная документация X-Cel.

## Продуктовые области

### Медицинская запись и заключение

Текущий реализуемый поток:

```text
ExamWriter RTF/TXT
  -> адаптер источника
  -> нормализованная MedicalRecord
  -> HTML/CSS или резервный PDF-рендер
  -> заключение
```

### База контактных линз

Принятое продуктовое направление:

```text
Проверяемые данные лабораторий
  + клинические правила врача
  + данные конкретного случая
  -> объяснимые потенциальные кандидаты
  -> окончательная оценка врачом
```

Границы функции и нерешённые вопросы описаны в `docs/features/contact-lens-knowledge-base.md`.

Принятая техническая цепочка:

```text
Локально кэшированные публичные источники
  -> манифест источников с версиями и SHA-256
  -> рецензируемые YAML-записи
  -> Pydantic-валидация
  -> декларативный rule engine
  -> объяснимый MatchResult с версиями и источниками
```

Архитектурное решение зафиксировано в `docs/adr/0001-contact-lens-knowledge-and-matching.md`.

## Границы безопасности

- Каталог изделий не является базой пациентов.
- Идентифицируемые пациентские данные не должны попадать в Git.
- Источник, редакция и дата проверки медицински значимого факта должны сохраняться.
- Отсутствующие клинические данные нельзя автоматически угадывать или подменять значением по умолчанию.
- Изменения клинических правил должны быть версионируемыми и проверяемыми на тестовых случаях.

## Неопределённости

- `UNKNOWN`: набор обязательных клинических входных данных для разных классов контактных линз.
- `UNKNOWN`: будущая модель пользователей, авторизации и хранения реальных пациентских данных.
- `UNKNOWN`: политика частного долговременного архива полных документов производителей.
- `OUT_OF_SCOPE`: доступность и регистрационный статус контактных линз в Казахстане.
- `DEFERRED`: противопоказания до отдельного изучения package inserts.
